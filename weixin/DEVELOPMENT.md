## 2026-08-30 · 推荐重选一致性修复

- 修复同分候选随机值相同导致推荐顺序长期不变的问题。
- 整组重推优先避开上一组的非固定菜，候选不足时才允许重复；用户主动固定的菜继续保留。
- 单道“换一道”只临时保留其他菜，不再把它们错误写入永久固定状态。
- 推荐诊断日志增加避让数量和实际替换数量，不记录菜名或菜谱正文。
- 新增随机换序与整组避让回归测试，与网站/Android 推荐行为保持一致。

## 2026-08-10 · 微信小程序完整迁移

### 目标

在官方模板基础上实现灶房全部核心业务，只修改 `weixin` 目录，保持本地优先、隐私安全和可供少量体验成员使用。

### 修改内容

- 建立四入口导航、统一视觉样式、页面错误处理和本地循环日志。
- 实现菜谱增删改查、搜索、十条分页、列表/缩略图切换、同名确认和待完善菜谱。
- 实现图片上传、HEIC 兼容处理、裁剪、50%–300% 缩放、旋转和平移。
- 实现本地人数加一推荐、固定/换菜/重选、餐次口味标签筛选和推荐历史。
- 实现六项健身营养指标、用户自选展示项、人数估重和 7,342 条本地食物数据库。
- 实现 AI 双入口、手动触发、图片能力测试、思考开关、响应兼容处理和按菜名 Token 日志/周月统计。
- 实现无压缩标准 ZIP 的流式导入导出，图片按 256 KB 分块，支持冲突预览、事务式回滚和大文件进度。
- 业务备份排除 API Key 与诊断日志；日志排除图片、密钥、提示词和完整菜谱正文。
- 营养库放入独立分包，测试与开发文档从上传包排除。

### 设计决定

- 小程序没有任意手机文件夹写权限，导出采用“本机生成 → 微信分享/文件面板保存”。
- 不启用微信云开发；设备之间默认不共享数据。
- AI 直接由小程序请求用户配置的服务，真机必须配置 `request 合法域名`。
- HEIC 转换失败时保留原图，仍可手动保存；只有 JPEG/PNG/WebP 才发送图片 AI。
- ZIP 使用 store 模式以降低移动设备 CPU 和峰值内存，换取略大的备份体积。

### 测试结果

- `npm run check`：通过。
- Node 测试：覆盖菜谱本地新增/修改/删除、去重、分页、推荐、营养、Token、AI 响应兼容、ZIP CRC/中文内容/标准兼容、超过 20 MB 图片流式导出和隐私边界。
- 微信开发者工具模拟器：应用启动、首页和推荐页加载日志正常，无运行时异常。
- 分包：完整营养库独立加载，避免占用主包配额。

### 已知平台限制

- 真机 AI 请求依赖公众平台合法域名、手机网络以及模型本身的视觉能力。
- 微信小程序无法弹出 Android 系统任意目录选择器。
- 原始 HEIC 能否直接解码取决于当前微信和系统；编辑保存后的 JPEG 可稳定预览和用于图片 AI。
